# Plan: Add exe.dev Quota Checker

## Summary

Add a quota checker (`exedev-checker`) for exe.dev that queries **two** API endpoints to produce a Shelley credit allowance meter. The checker uses a bearer token for the `/exec` API and an optional session cookie for the `/api/llm-usage` web dashboard endpoint.

## API Endpoints & Response Shapes (verified from live account)

### Endpoint 1: `POST https://exe.dev/exec` → body: `billing plan --json`

Auth: `Authorization: Bearer <apiKey>`, `Content-Type: text/plain`, body = command string.

**Verified working** with bearer token (tested with `ssh-key generate-api-key --cmds "billing plan"`).

```json
{
  "bandwidth_gb": 200,
  "billing_period_end": "2026-06-01",
  "billing_status": "active",
  "cancel_at_period_end": false,
  "default_disk_gb": 25,
  "has_monthly_refresh": true,
  "max_cpus": 2,
  "max_disk_gb": 75,
  "max_memory_gb": 8,
  "max_vms": 50,
  "monthly_price_cents": 2000,
  "paid": true,
  "per_seat": false,
  "plan": "Individual",
  "plan_id": "individual:small:monthly:20260106",
  "pooled_disk_gb": 100,
  "shelley_credits_max": 20,
  "status": "active",
  "status_label": "Active",
  "tier": "Small"

```

Key fields:
- `shelley_credits_max` — monthly Shelley credit allowance (in USD, e.g. 20 = $20)
- `billing_period_end` — ISO date string for when the allowance resets (e.g. `"2026-06-01"`)
- `has_monthly_refresh` — boolean, whether credits refresh monthly

### Endpoint 2: `GET https://exe.dev/api/llm-usage`

Auth: `Cookie: exe-auth=<session>` (bearer token does **not** work for this endpoint — confirmed).

```json
{
  "days": [
    {
      "day": "2026-05-21",
      "entries": [
        {"box": "ykonyx", "model": "accounts/fireworks/models/kimi-k2p6", "provider": "fireworks", "cost": "$0.30", "requestCount": 42}
      ],
      "cost": "$0.73",
      "count": 168
    }
  ],
  "totalCost": "$2.01",
  "totalCount": 308,
  "periodStart": "2026-05-01T00:00:00Z",
  "periodEnd": "2026-06-01T00:00:00Z"
}
```

Key fields:
- `totalCost` — string like `"$2.01"`, strip `$` prefix and parse as float → the `used` amount against the Shelley allowance
- `periodStart` / `periodEnd` — ISO timestamps for the billing period

### NOT USED: `billing usage --json`

Returns only VM/disk/CPU data (no Shelley credit info). Omitted since we're tracking Shelley credits only.


## Implementation

### 1. Create `packages/backend/src/services/quota/checkers/exedev-checker.ts`

```typescript
import { defineChecker } from '../checker-registry';
import { z } from 'zod';
import { logger } from '../../../utils/logger';
```

- **type**: `'exedev'`
- **displayName**: `'exe.dev'`
- **optionsSchema**:
  - `apiKey` (required, `z.string().min(1, 'exe.dev API bearer token is required')`) — bearer token for `/exec` API (from `ssh exe.dev ssh-key generate-api-key --cmds "billing plan"`)
  - `session` (optional, `z.string()`) — exe.dev session cookie value (`exe-auth`) for `/api/llm-usage`. If not provided, the `used`/`remaining` fields will be unavailable and utilization will be `unknown`.
  - `endpoint` (optional, `z.string().url()`) — defaults to `https://exe.dev/exec`
  - `llmUsageEndpoint` (optional, `z.string().url()`) — defaults to `https://exe.dev/api/llm-usage`

#### `check()` logic

Make **2** HTTP requests (or 1 if no session):

1. **`POST {endpoint}`** with body `billing plan --json` → get `shelley_credits_max`, `billing_period_end`, `has_monthly_refresh`
   - Headers: `Authorization: Bearer <apiKey>`, `Content-Type: text/plain`
   - If this fails, throw immediately (this is the critical call)

2. **`GET {llmUsageEndpoint}`** (only if `session` option provided) → get `totalCost`
   - Headers: `Cookie: exe-auth=<session>`, `Accept: application/json`
   - If this fails or `session` is absent, still produce the meter with `limit` only (graceful degradation)

Helper function `parseDollars(s: string): number` — strips leading `$`, parses as float.

Derive `remaining = shelley_credits_max - used` (only if `used` is available).

#### Meters produced

| # | Meter key | Kind | Label | Fields | Unit | Period |
|---|-----------|------|-------|--------|------|--------|
| 1 | `shelley_credits` | allowance | Shelley credits | `limit` from `shelley_credits_max`; `used` from `totalCost` (if session available); `remaining` derived | `usd` | `periodValue: 1, periodUnit: 'month', periodCycle: 'fixed'`, `resetsAt` from `billing_period_end` |

The `resetsAt` is derived from `billing_period_end` (e.g. `"2026-06-01"` → `"2026-06-01T00:00:00Z"`). If `has_monthly_refresh` is false, omit `resetsAt` and set `periodCycle` to `'rolling'`.

**Only one meter** — we don't have an API endpoint for extra credits yet, so we don't produce that meter. The dashboard HTML showed an "EXTRA CREDITS" card but there's no documented API to retrieve it programmatically.

## Notes

- The exe.dev HTTPS `/exec` API uses bearer token auth. Tokens are generated via `ssh exe.dev ssh-key generate-api-key --cmds "billing plan"`. The `cmds` permission must include `"billing plan"` (or a broader permission like `"billing"`).
- The `/api/llm-usage` endpoint is a **web dashboard endpoint** that requires cookie auth (`exe-auth`). Bearer tokens do **not** work for this endpoint (confirmed by testing).
- `/exec` POST body is plain-text command string (not JSON). Content-Type: `text/plain`.
- `/api/llm-usage` returns `totalCost` as a formatted string like `"$2.01"` — must strip `$` and parse as float.
- If `session` cookie is not configured, the checker degrades gracefully: it reports the `limit` from `shelley_credits_max` but leaves `used`/`remaining` unknown, resulting in `utilizationPercent: 'unknown'` and `status: 'ok'`.
- No database schema changes needed — meters are persisted by the existing `QuotaScheduler.persistResult()`.
- `billing usage --json` is intentionally **not** called — it only returns VM/disk/CPU data, not Shelley credit info.
